# Тестовое приложение с кеширующим слоем

Проект реализует многоуровневую архитектуру с кешированием данных из PostgreSQL через Redis.

##  Описание

Приложение состоит из двух основных компонентов:
- **Backend API** (Go) — работает с PostgreSQL, предоставляет данные через REST API
- **Proxy API** (Python/Flask) — кеширующий прокси-слой, проверяет данные в Redis перед обращением к Backend

### Логика работы
1. Клиент делает запрос к Proxy
2. Proxy проверяет наличие данных в Redis
3. Если данные есть (`cached: true`) — сразу возвращает их
4. Если данных нет (`cached: false`) — запрашивает у Backend, сохраняет в Redis и возвращает клиенту

### Виртуальные машины
| ВМ  |      ОС         | Компоненты               | IP             |
|-----|-----------------|--------------------------|----------------|
| VM1 | Ubuntu 24.04    | Backend API + PostgreSQL | 192.168.200.10 |
| VM2 | CentOS Stream 9 | Proxy API + Redis        | 192.168.200.11 |

### Сетевые правила
| Сервис   | Порт | Доступ от                 | Описание         |                  
|----------|------|---------------------------|------------------|
|Proxy     | 5000 | 0.0.0.0/0                 | Публичный доступ |
|Backend   | 8080 | 192.168.200.11            | Только от Proxy  |
|PostgreSQL| 5432 | 127.0.0.1, 192.168.200.10 | Только локально  |
|Redis     | 6379 | 127.0.0.1                 | Только локально  |

Backend API принимает запросы только от Proxy (192.168.200.11)
PostgreSQL доступен только локально
Redis доступен только локально
Proxy API — единственная публичная точка входа

Для применения правил фаерволла необходимо запустить скрипт rules.sh, предварительно раскомментировав одну из строк в конце файла:
- для backend (Ubuntu) --  apply_backend_rules
- для proxy (CantOS) -- apply_proxy_rules
